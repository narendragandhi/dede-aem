# Specification: ForbiddenApiScanner — malicious code pattern detection

## Overview

**Feature**: `scanForMaliciousPatterns(Path projectRoot)` method on `ForbiddenApiScanner`
**Purpose**: Detect multi-step supply chain attack patterns that cannot be expressed as single
class/method entries in `forbidden-apis.json`. These require cross-statement AST analysis.

## Context

SC-001 adds single-symbol forbidden entries (Runtime, URLClassLoader, etc.). However the most
dangerous supply chain patterns in real malicious packages are *combined*:

| Pattern | Why dangerous |
|---------|--------------|
| `Base64.getDecoder().decode(…)` + `exec(new String(…))` | Obfuscated command execution |
| Static initializer `<clinit>` opening a `Socket` or `URL` | Runs at class-load time, before @Activate |
| `@Activate` / `@Modified` method calling `ProcessBuilder` | Lifecycle hook used as trojan trigger |

These are the same heuristics supply-chain-monitor injects into its LLM prompt. Here we detect them statically via JavaParser AST.

## Functional Specification

### New Method

```java
public List<MaliciousPatternViolation> scanForMaliciousPatterns(Path projectRoot)
```

Returns a list of findings. Each finding represents one dangerous multi-step pattern.

### Record

```java
public record MaliciousPatternViolation(
    String filePath,
    int line,
    MaliciousPatternType patternType,
    String detail,
    ForbiddenApiCatalog.Severity severity
) {}

public enum MaliciousPatternType {
    OBFUSCATED_EXEC,       // Base64 decode result passed to exec/ProcessBuilder
    STATIC_INIT_NETWORK,   // Static initializer opens Socket, URL, or URLConnection
    LIFECYCLE_PROCESS_SPAWN // @Activate/@Modified/@Deactivate calls exec/ProcessBuilder
}
```

### Detection Rules

#### OBFUSCATED_EXEC
- AST condition: `MethodCallExpr` with name `exec` or ProcessBuilder init whose argument
  contains a `MethodCallExpr` with name `decode` (Base64 decoder)
- Confidence: HIGH (pattern is nearly always malicious in OSGi bundles)
- Severity: CRITICAL

#### STATIC_INIT_NETWORK
- AST condition: `InitializerDeclaration` with `isStatic() == true` that contains any
  `ObjectCreationExpr` for `java.net.Socket`, `java.net.URL`, or `java.net.URLConnection`
- Severity: CRITICAL

#### LIFECYCLE_PROCESS_SPAWN
- AST condition: `MethodDeclaration` annotated with `@Activate`, `@Modified`, or `@Deactivate`
  that contains a `MethodCallExpr` for `exec` or an `ObjectCreationExpr` for `ProcessBuilder`
- Severity: CRITICAL

### Graph Integration
For each finding, create a `VULNERABILITY` node (same as existing `ForbiddenApiScanner` violations)
with `metadata.category = patternType.name()` and link it to the source `CLASS` node via `EXPOSES`.

## Acceptance Criteria

- [ ] `scanForMaliciousPatterns(Path)` returns findings for all three pattern types
- [ ] Each `MaliciousPatternViolation` has non-null filePath, line > 0, and a severity
- [ ] VULNERABILITY nodes created in graph for each finding
- [ ] No false positives on the dede-java codebase itself
- [ ] All 116 baseline tests still pass
