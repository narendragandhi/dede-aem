### Implementation Sketch

```java
public List<MaliciousPatternViolation> scanForMaliciousPatterns(Path projectRoot) {
    List<MaliciousPatternViolation> findings = new ArrayList<>();
    try (var stream = Files.walk(projectRoot)) {
        stream.filter(p -> p.toString().endsWith(".java"))
              .forEach(file -> findings.addAll(scanFileForMaliciousPatterns(file)));
    }
    findings.forEach(this::createVulnerabilityNodeForMalicious);
    return List.copyOf(findings);
}

    //   visit(MethodCallExpr n, ...)         -> check OBFUSCATED_EXEC
}
```

### AST Helpers

**OBFUSCATED_EXEC**: Inside any `MethodCallExpr` named `exec` or `ProcessBuilder` constructor,
check if any argument `MethodCallExpr` has name `decode`.

**STATIC_INIT_NETWORK**: In `InitializerDeclaration` with `isStatic()`, look for
`ObjectCreationExpr` where type name is in `{"Socket", "URL", "URLConnection"}`.

**LIFECYCLE_PROCESS_SPAWN**: In `MethodDeclaration`, check annotations for
`@Activate`, `@Modified`, `@Deactivate` (simple name check), then scan method body for
`MethodCallExpr` named `exec` or `ObjectCreationExpr` named `ProcessBuilder`.

### Reuse Pattern
Follow the existing `createVulnerabilityNode(ForbiddenApiViolation v)` pattern for graph node creation.
Use `metadata.put("maliciousPattern", patternType.name())` to distinguish from catalog violations.
